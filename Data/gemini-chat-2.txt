Tier	Category	Content Signal	Action

Don't just search for "RCA". Use a scoring system in your code:

Score 100: Comment contains "RCA:" or "Root Cause:".

Score 50: Comment contains keywords like "fixed," "unlocked," "updated," or "mapped."

Score 0: Comment is under 30 characters (e.g., "Done").

For tickets like SWSUP-54 (the login issue), where the fix is mentioned but not labeled:

Pass the Summary + Cleaned Comments to an LLM.

Prompt: "Identify the problem and the resolution from this ticket."

Output: Save it as a structured object: { "Problem": "Login issue", "Solution": "Unlock user account" }.

This extended data confirms a pattern: the most valuable "RCA" information is buried in the middle of long email chains, and the "Final Comment" is often just a polite confirmation ("Now it's working fine").

To make XBRLSupportBot truly smart, you need to solve the "Noise-to-Signal" problem. Here is how you can manage this data efficiently using your .NET and React stack.

1. The "Recursive Cleaner" Algorithm
The biggest issue in your JSON is that each comment often contains the entire previous history of the ticket. If you feed this to an AI, it will see the same text 10 times and get confused.

The Fix (.NET Core Logic):
When processing the body of each comment, apply these filters in order:

Split by Email Headers: Truncate the string at the first occurrence of From:, Sent:, or Subject:. This removes the historical "tail."

Strip Signatures: Use Regex to remove standard footers (e.g., "This email and any attachments are confidential...").

Deduplication: If a cleaned comment's text is already present in a previous comment within the same ticket, discard it.

2. Transitioning to a "Problem-Solution" Schema
Instead of keeping the "Messy Jira" structure, transform your data into a Knowledge Base Schema. This is what your React app should eventually use for the bot's "brain":

Field	Source / Logic
IssueID	key (e.g., SWSUP-43)
Context	summary (e.g., "Unable to generate output")
Technical Symptoms	Extract from the first comment or description.
Root Cause (RCA)	Search comments for keywords: RCA, cause, because, due to, mismatch.
Resolution	Search for: fixed, resolved, updated, unlocked.
Tags	Extract taxonomy elements (e.g., NonVariableAnnuitiesLineItems).
3. Handling the "Missing RCA" Tickets
For tickets like SWSUP-43, the developer (Kalangiyam) explains exactly what is wrong ("LineItems is not created under the table in presentation tree") but doesn't use the word "RCA."

The Solution:
Instead of a simple keyword search, use a Weighted Keyword Map in your .NET backend to "Score" a comment for useful knowledge:

Taxonomy Keywords (+20 points): "Element," "Tag," "Hierarchy," "Presentation Tree," "LineItems."

Action Keywords (+10 points): "Created," "Updated," "Moved," "Arranged."

Vague Keywords (-10 points): "Kindly check," "Please confirm," "ASAP."

Result: Any comment with a score > 30 is automatically flagged as a "Knowledge Snippet" for the bot, even if the word "RCA" is missing.

4. Implementation Step: The .NET "Parser"
Since you are using .NET Core, you can create a simple CleanComment utility.

C#
public string CleanJiraComment(string rawBody) {
    // 1. Remove the email thread tail
    var cleaned = rawBody.Split(new[] { "From:", "Sent:", "Subject:" }, StringSplitOptions.None)[0];
    
    // 2. Remove common signatures
    cleaned = Regex.Replace(cleaned, @"This email and any attachments.*", "", RegexOptions.Singleline);
    
    // 3. Remove URLs and extra whitespace
    cleaned = Regex.Replace(cleaned, @"http[^\s]+", "");
    
    return cleaned.Trim();
}
5. Next Strategic Goal: Vectorization
Once you have this cleaned text, don't just put it in a spreadsheet. To make XBRLSupportBot conversational:

Embed the Data: Turn the cleaned "Problem + Solution" strings into vectors (mathematical representations of meaning).

Semantic Search: When a user asks "Why is my output failing?", the bot doesn't look for the word "failing"—it looks for the meaning of an output error and finds the "End tag mismatch" or "LineItems hierarchy" issues you just processed.

Issue Key: (e.g., RAIN-4472)

Step 2: Knowledge Categorization (Taxonomy)
Efficient bots don't search all data at once. Organize the data into "Folders" or "Namespaces" based on the Dolphin Program/Group or Error Category.

Category A: Rendering Issues (Superscripts, alignment, font bleeding).

Category B: Calculation Issues (Summation errors, scale mismatches).

Category C: Workflow/Status (ETA delays, QC bottlenecks).

Step 3: Implement Semantic Search (Vectorization)
To get "better performance," the bot shouldn't just look for words; it should understand intent.

private string CleanJiraText(string text)
{
    if (string.IsNullOrEmpty(text)) return string.Empty;
    // Remove HTML tags, non-breaking spaces, and excessive newlines
    var clean = System.Text.RegularExpressions.Regex.Replace(text, "<.*?>", string.Empty);
    clean = clean.Replace("&nbsp;", " ").Replace("\\r\\n", " ");
    return clean.Trim();
}

Here is a breakdown of what "Vectorization" actually is and why you need it for your XBRLSupportBot.

1. What is a "Vector" (The Simple Version)
In standard coding, you use String.Contains() or SQL LIKE %text%. This only works if the user types the exact word.

Vectorization turns text into a list of numbers (a "Vector") that represents the meaning of the text.

The word "Superscript" and the word "Formatting" will have "numbers" that are mathematically close to each other.

This allows your bot to find RAIN-4472 even if the user asks: "Why is my font floating above the line?" (even though the word "floating" isn't in your Jira ticket).

2. The Workflow Breakdown
A. Generate a "Search String"
Instead of vectorizing the whole email chain (which is expensive and noisy), you create a concentrated "Knowledge Nugget."

Code Logic: string knowledgeNugget = $"Issue: {ticket.Summary}. Root Cause: {ticket.RcaComment}. Fix: {ticket.Workaround}";

B. Get Embeddings (The Cost Part)
You send that knowledgeNugget to an API (like OpenAI).

Cost: Currently, OpenAI’s text-embedding-3-small model costs about $0.02 per 1 million tokens.

Your Project: 100 Jira tickets is roughly 50,000 tokens. Cost to vectorize your entire database: $0.001 (one-tenth of a cent).

C. Store in a Vector Database
A "Vector Database" is a special library that can do "math" on those lists of numbers to find the closest match.

Qdrant / Pinecone: Both have Free Tiers that are more than enough for your current data.

Azure SQL: If your company already pays for SQL Server, you can use the new VECTOR data type for free.
